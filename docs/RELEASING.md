# Releasing

One tag ships everything. Pushing `vX.Y.Z` starts three workflows:

- `release.yml` (generated by [dist](https://axodotdev.github.io/cargo-dist/))
  builds the `tether` binary for macOS and Linux, on arm64 and x86-64, and
  puts the archives, their checksums and `tether-cli-installer.sh` on a GitHub
  release.
- `pypi.yml` builds `sdks/python` and publishes it to PyPI as `tether-agents`.
- `npm.yml` builds `sdks/typescript` and publishes it to npm as
  `tether-agents`.

`tetherd` is not shipped as a binary of its own. The `tether` binary carries
the daemon as `tether daemon`, and the SDKs start it that way when no
`tetherd` is on `PATH`.

## Steps

1. Set the version in three places, to the same value: `version` under
   `[workspace.package]` in `Cargo.toml`, `version` in
   `sdks/python/pyproject.toml`, and `version` in
   `sdks/typescript/package.json` (then `npm install` there, so
   `package-lock.json` follows). Run `cargo check` so `Cargo.lock` follows.
   Each workflow refuses a tag that does not match its version. In
   `CHANGELOG.md`, rename "Unreleased" to the version and today's date, and
   start a new empty "Unreleased" above it.
2. Merge that to `master`.
3. Tag the merge commit and push the tag:

   ```sh
   git tag v0.4.0
   git push origin v0.4.0
   ```

4. Watch the three workflows. A version on PyPI or npm cannot be published
   twice: if a package was published and another workflow failed, fix it and
   re-run that workflow instead of moving the tag.

## One-time setup

- **PyPI.** Publishing uses trusted publishing, so no token is stored. On
  PyPI, add a trusted publisher for the project `tether-agents` (a pending
  publisher, before the first release): this repository, workflow `pypi.yml`,
  environment `pypi`.
- **npm.** Also trusted publishing. In the package's settings on npmjs.com,
  add a trusted publisher: GitHub Actions, this repository, workflow
  `npm.yml`, environment `npm`. If npm will not take a publisher for a
  package that does not exist yet, publish the first version by hand
  (`npm login`, then `npm publish --access public` in `sdks/typescript`) and
  add the publisher afterwards.
- **GitHub.** Create environments named `pypi` and `npm` in the repository
  settings. Adding a required reviewer to each makes a publish wait for
  approval.

## Changing the release build

`release.yml` is generated. Edit `dist-workspace.toml` and run
`dist generate`; a hand edit makes the workflow's own check fail. To see what
a release would contain without building it, run `dist plan`.

There is no Windows build: the daemon listens on a Unix socket and the
process sandbox uses Unix process groups and rlimits.
